# 07 核心算法一至三

七、核心算法一：比例、加权汇总和金额口径

每个比例必须说明：
分子、分母、对象、时间、状态、去重方式和归因范围。

公式：

CTR = 对应点击数 / 对应曝光数

CVR = 转化数 / 约定的行为基数
必须说明是支付订单/点击，还是支付人数/访问人数等口径。

平台归因ROI = 平台归因成交金额 / 对应广告消耗
必须说明归因模型、时间窗口和成交金额定义。

总体比例 = 各组分子合计 / 各组分母合计
不能直接平均各组百分比。

总体ROI = 各组对应成交金额合计 / 各组对应消耗合计

平均每单实付 = 用户实付合计 / 对应订单数
不能把它称作平均每位顾客消费。

退款订单比例 =
有退款的去重订单数 / 同一购买批次的支付订单数

退款金额比例 =
对应退款金额 / 口径一致的原成交金额
如果补贴、币种、退款范围不一致，暂不计算或明确限制。

核销订单比例 =
至少有一次有效核销的去重订单数 / 同批次支付订单数

核销券比例 =
有效核销的去重券数 / 同批次购买券数

已退款订单是否从分母剔除，取决于要回答的问题：
默认保留原支付批次作为分母。
若分析未退款订单，必须另列指标并明确说明。
不得通过剔除失败订单让比例变好看。

分母为0时：
显示“不可计算”，不能显示0%。

金额必须区分：
用户实付、订单实收、预计收入、退款、结算收入、利润。

未经对账，不得把：
用户实付－退款
或
订单实收－退款
自动称为净收入。

缺少履约成本、服务费、补贴处理等信息时，不计算利润。


八、核心算法二：描述分布，不只报告总数

根据问题选择必要指标：

- 总量；
- 日均；
- 均值；
- 中位数P50；
- P25、P75；
- 必要时P90；
- 最小值、最大值；
- 标准差；
- 各组占比；
- 头部集中度。

分位数采用的方法应保持一致，例如线性插值。
不能混用不同分位数算法再比较微小差异。

均值 = 数值合计 / 记录数量

样本标准差 =
sqrt[Σ(x－均值)² / (n－1)]
n小于2时不可计算样本标准差。

变异系数 = 标准差 / 均值
仅在均值为正且有解释意义时使用。

变化金额 = 本期－基期

相对变化 = (本期－基期) / 基期
基期为0时不输出普通增长率。

百分点变化 = 本期比例－基期比例

例：
CTR从4%升到5%，是提高1个百分点，
相对提升25%，不是“提升1%”。

使用IQR检查异常候选：
IQR = P75－P25
低于P25－1.5×IQR，或高于P75＋1.5×IQR的记录可标记待查。
这只是筛查规则，不是删除依据。

样本只有9天时，可以报告这9天的范围和标准差，
不能直接称其为稳定的正常区间。

均值的置信区间、未来一天的预测区间、控制图界限是不同概念，
不得相互替代。


九、核心算法三：同批次、同观察年龄的核销与退款

这是本地生活分析的重点。

定义：

t0 = 每笔订单的支付时间
T = 可靠的数据观察截止时间
H = 指定观察时长，例如24小时、72小时、7天

某笔订单可进入H窗口分析的条件：
t0 + H <= T

H窗口核销订单比例 =
满足成熟条件、且支付后H内至少有一次有效核销的订单数
/
满足成熟条件的支付订单数

H窗口退款指标也采用相同的成熟条件。
必须说明衡量的是“首次退款”还是“全部退款完成”。

未核销、未退款的成熟订单仍保留在原始分母中。
不足H的订单不进入这一固定窗口比较，单独报告数量。

禁止：
- 把今天核销额除以今天成交额，称作真实核销率；
- 用新订单的1天结果与老订单的9天结果直接排名；
- 把截至目前未核销当作永远不会核销；
- 把不同购买批次的24小时率和72小时率相减，
  声称得到了第2—3天新增核销率。

要研究核销随时间的增长：
必须对同一成熟批次计算多个观察节点，
或者在条件充分时使用合适的生存分析方法。

核销速度的中位数如果只在已核销订单中计算，
必须标注“仅在已观察到核销的订单中”，
不能说成所有顾客通常多久核销。
