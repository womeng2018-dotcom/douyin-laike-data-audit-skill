# 13 抖音来客 / 本地推 字段口径与陷阱

> 本文件是**领域附录**，不是规范原文。它把规范里抽象的原则，落到抖音来客（本地生活）
> 后台真实导出的表名、字段名和已经踩过的坑上。
> 目的是让分析者在第一次看到表头时就知道：**哪些列能放一起算，哪些列放一起一定会错。**

---

## 一、常见导出表与它们的"一行是什么"

后台导出的口径经常变，所以**永远先用 `scripts/contract.py` 体检，不要凭本表下结论**。
下面是最常见的几种表及其粒度：

| 表 | 典型文件名 | 一行是什么 | 常见主键 | 陷阱 |
|---|---|---|---|---|
| 按日趋势 | `按日趋势.csv`、`数据概览.csv` | 一天 | 日期 | 缺日期不补；文件名日期 ≠ 数据日期 |
| 计划对比 | `计划对比.csv`、`计划数据.csv` | 一个计划（或计划×日） | 计划名称 | 计划名内嵌日期与预算，**不是 ID**；改名即断链 |
| 素材数据 | `素材数据.csv`、`视频数据.csv` | 一条素材（或素材×日） | 素材ID／视频ID | 常缺"素材ID"列，只有标题文本 |
| 门店明细 | `门店明细.csv` | 一个门店（或门店×日） | 门店名称（**常无门店ID**） | 同名门店、名称带括号后缀，跨表对不上 |
| 订单明细 | `订单明细.csv` | **一笔订单** | 订单ID | 金额有多个口径：实付／实收／券面价 |
| 券／核销明细 | `核销明细.csv`、`券码明细.csv` | **一张券** | 券码 | 一单多券 → 行数 ≠ 订单数 |
| 退款明细 | `退款明细.csv`、`售后明细.csv` | **一次售后事件** | 退款单号 | 部分退款、多次退款、撤销退款 |
| 达人／分销 | `达人数据.csv` | 一位达人（或达人×日） | 达人ID／昵称 | 结算口径与平台口径不同 |

## 二、字段口径映射（后台字段 → 我们的口径名 → 陷阱）

### 投放侧

| 后台字段 | 我们的口径 | 陷阱 |
|---|---|---|
| 消耗 | 广告消耗 | 含税/不含税、是否含赠款，需确认 |
| 成交金额 | **平台归因成交金额** | ⚠️ 常是"全域成交"或"归因成交"，**范围远大于广告**。绝不能称作"广告新增成交" |
| 订单数 | 平台归因订单数 | 归因窗口不同则不同 |
| 成单人数 | 去重成单人数 | 与订单数分母不同，**不能互相套用** |
| ROI | 成交金额 ÷ 消耗 | 行内自洽 ≠ 口径正确（自洽只说明除法没错） |
| 订单成本 | 消耗 ÷ 订单数 | 同上 |
| 日均消耗 | 消耗 ÷ 天数 | 天数口径必须与"投放天数"一致 |
| 曝光 / 展示 | 曝光数 | 有曝光才能算 CTR |
| 点击 | 点击数 | 有点击才能算点击率 |
| 商品访问 / 详情页浏览 | 访问数 | **CVR 分母的候选，必须确认用哪个** |

**关键问句（回后台核对）**：成交金额是实付还是券面价？扣退款了吗？到期未核销的券算不算？
归因窗口是 1 天／7 天／24 小时？ROI 的分子范围（全域／广告归因／货架）+ 分母范围是否一致？

### 交易侧

| 后台字段 | 我们的口径 | 陷阱 |
|---|---|---|
| 用户实付金额 | 用户实付 | ≠ 订单实收（差 1~2 元很常见，来自优惠/补贴） |
| 订单实收 / 商家实收 | 订单实收 | 与实付的差必须解释清楚，**不要把差额当亏损** |
| 券面价 / 门市价 | 券面价 | 不等于收入 |
| 购买数量 | 订单购买总数 | ⚠️ 在**核销行里**它往往是原订单购买总数，**逐行相加会翻倍** |
| 核销金额 | 核销金额 | 部分核销时按次计，与订单金额口径不同 |
| 退款金额 | 退款 | 用 `-` 表示"无退款"时是**缺失，不是 0** |
| 结算金额 / 预计收入 | 结算收入 | 平台扣佣后，口径与实收不同 |
| 订单状态 | 状态 | 类别可能不互斥（如"已完成"与"已核销"并存） |

**金额口径六级**（必须逐级区分，不能跳级）：
`用户实付 → 订单实收 → 预计收入 → 退款 → 结算收入 → 利润`
未对账，不得把"实付 − 退款"或"实收 − 退款"称为净收入；缺履约成本、服务费、补贴处理时不计算利润。

### 履约侧

| 后台字段 | 我们的口径 | 陷阱 |
|---|---|---|
| 核销时间 | 核销事件时间 | 一单多券 → 多行、多个时间 |
| 核销状态 | 状态 | "已核销/未核销/已过期"是否互斥需确认 |
| 有效期 / 到期日 | 券有效期 | 过期未核销 ≠ 永远不会核销，但影响"成熟"判断 |
| 退款完成时间 | 退款事件时间 | 申请时间 ≠ 完成时间，撤销后时间仍在 |
| 撤销 / 部分退款 | 事件变更 | 缺少该历史时，**无法精确重建历史状态** |

## 三、已经踩过的真实坑（务必逐条检查）

以下每一条都在真实数据里发生过，且都会导致结论错误。

### 坑 1 · 表内自洽 ≠ 口径正确
某批数据里，`ROI = 成交金额 ÷ 消耗`、`订单成本 = 消耗 ÷ 订单数` 对 57 家门店逐行复算
**0 行不一致**。但"自洽"只说明这几列是同一组底层数字的几种除法，**不说明分子分母范围一致**。
同一批数据里，全域口径 ROI ≈ 125~145，而素材直接归因口径 ROI ≈ 8.86，**差约 15 倍**。
→ 看到超高 ROI，第一反应是查分母范围，不是庆祝。

### 坑 2 · 同一时间段，两套口径对不上账
| 口径 | 消耗 | 成交金额 | 订单数 |
|---|---|---|---|
| 阶段对比 · 8月段（10 天） | 7911.96 | 989159.8 | 8926 |
| 按日趋势 8-04~8-13 汇总 | 2577.56 | 294626.2 | 2647 |
| 门店明细（57 家）汇总 | 2555.46 | 291209.2 | 2616 |

按日趋势恰好等于**单条计划**；而"阶段对比"多了约 **5334 元（≈67%）** 消耗、约 69.5 万成交。
→ **这是两套不同的覆盖范围，不是误差。** 在解释清楚缺口之前，禁止做跨口径比较。
→ 规矩：**每次跨表汇总都必须 `reconcile.py group` 回加总量。**

### 坑 3 · 看起来像连续 28 天，实际缺了 9 天
"按日趋势"有 28 行，实际是 7 月段 18 天 + 8 月段 10 天，中间 **07-26 ~ 08-03 缺 9 天**，
且起始不是自然月首日。星期分布也不均（周三 5 天、周日仅 3 天）。
→ 直接算"日均""分周日比较"都会被扭曲。必须报告缺口，并用 `contract.py` 的日期连续性检查。

### 坑 4 · 只有已核销记录，推不出核销率
某核销表样本 = 单店 112 笔**已核销**记录：92.86% 当天核销、97.32% 三天内、14 天覆盖 100%。
这张表**没有未核销订单作为分母** → 只能回答"**已核销者**何时核销"，
**不能推出核销率**；也不能把"核销率约 30%"（另一个历史全量口径）与之混用。
→ 规矩：只统计到已发生事件的对象时，必须标注"**仅在已观察到核销的订单中**"。

### 坑 5 · 期限评估表要看清分母
`期限评估_覆盖率.csv` 有"期限T(天) / 可完整观测订单数 / T天内核销占比%"三列——
这正是**成熟批次**的正确做法（可完整观测订单数随 T 增大而减少）。
→ 好表：它把"可完整观测"写进了分母。分析时必须沿用这个约束，
不能把 T=7 的 99.02% 与 T=14 的 100% 直接相减说成"第 8–14 天新增核销 0.98%"，
除非确认两者是**同一批对象**。

### 坑 6 · 没有唯一 ID，硬关联一定错
门店只有**名称文本**；计划名内嵌日期（如 `..._0717`）；被引用的素材明细文件可能**根本不在本地**。
→ 无唯一 ID 时**不能做素材 × 门店关联**。硬拼会得到看起来合理但完全错误的归因。
→ 规矩：找不到关联键时，**保留分表分析**，并在"不能下的结论"里写明。

### 坑 7 · 缺少曝光/点击字段 → 不能算 CVR／CTR
一批只有"消耗／成交／订单数"的文件里**没有曝光、点击、访问字段**。
→ 说"CTR 提升""CVR 下降"就是编造。必须明确写"**数据不足**，等后台导出含点击、访问的报表"。

### 坑 8 · 部分日不能与完整日比较
日趋势的**最后一行常常是未结束的一天**（或导出时当天数据未回传完全）。
→ 用 `开始时间 <= 业务时间 < 次日00:00` 判断完整自然日；未结束的一天单独标注，不参与日均。

### 坑 9 · 状态类别不互斥
"已完成""已核销""已退款"可能同时出现在一行，或同一订单在多表中各有一种状态。
→ 不互斥时**不能强行相加**；须用 `reconcile.py partition` 检查。

### 坑 10 · 用户口述数字与表格数字混用
经营者常凭记忆说"这几天差不多一天卖 3 万"。这类数字必须标注
"**用户提供，尚未与后台核对**"，不能与表格结果放在同一列相加或相除。

## 四、开工前的口径问句清单（直接发给经营者／运营）

把这些问题一次问完，比事后返工便宜得多：

1. 这段时间的**成交金额**是实付还是券面价？**扣退款了吗**？到期未核销的券算不算？
2. **ROI** 的成交范围是全域／广告归因／货架？**归因窗口**几天？
3. 有没有**曝光、点击、商品访问**字段？没有的话本次不产出 CTR／CVR。
4. 核销表里**一行是一张券还是一笔订单**？"购买数量"是本次核销数还是订单购买总数？
5. 退款金额的 `-` 代表**没有退款**还是**未采集**？有没有**撤销退款**的记录？
6. 各表能不能用**订单ID / 券码 / 门店ID / 素材ID** 关联？有唯一 ID 吗？
7. 本次要回答的是"**9 月 1–9 日购买的订单**在导出时的状态"，还是"**9 月 1–9 日发生的所有事件**"？
8. 有没有**未导出的表**（素材明细、达人结算、履约成本）？缺了就要在结论里写清。
9. 这段时间内**发生过哪些干预**（改价、上架、停投、换素材、门店装修、平台活动）？
10. 有没有**同期的对照**（未投放城市/门店、历史基线），用于区分"时间关联"和"因果"？

## 五、抖音来客场景下的高频正确表述模板

| 场景 | ❌ 不能说 | ✅ 应该说 |
|---|---|---|
| 高 ROI | "ROI 145，投一赚一百四十五" | "平台归因成交 ÷ 消耗 = 145；归因窗口 __ 天，成交金额口径为 __；**这不等于广告新增成交**" |
| 核销率 | "今天核销率 30%" | "在 `t0 + 24小时 <= T` 的 __ 笔成熟订单中，24 小时内至少一次有效核销的比例 = __%（分子 __ / 分母 __）" |
| 门店排名 | "A 店比 B 店好" | "同口径、同天数、同观察年龄下，A 店与 B 店的 __ 差异为 __；未控制 __，不能排除混杂" |
| 素材效果 | "这条素材最好" | "本轮第 __ 名；观察年龄不同/样本 __，只能作为**探索性筛查**，需在下一轮用等预算、同窗口复测" |
| 退款 | "这笔亏了 1 元" | "实付 98、实收 100、退款 99；实付与实收差 2 元来自优惠/补贴，**口径未对账前不能判定盈亏**" |
| 投放效果 | "投了两天多卖了 3 万" | "投放两天成交 6 万，消耗 400；**缺少无投放对照**，只能算时间关联，不能主张新增" |
| 数据缺失 | "大致差不多" | "**数据不足**：缺少 __ 字段／__ 表；需要的证据是 __" |

## 六、给别人做交付时的三句话

1. 我用了什么表、什么时间窗、什么状态、什么口径 —— 写在最前面。
2. 哪些数字是**程序算出来的、你能自己复算**的 —— 每个数字带分子分母。
3. 哪些问题**这次答不了、需要补什么** —— 单列一节，不含糊。
